# Plain technical mode (ASD-STE100 rules)

These rules apply to text that a person or an agent must act on without asking the author anything: tool descriptions, error messages, procedures, system prompts, agent instructions, status reports, READMEs, and PR descriptions. They come from ASD-STE100 Simplified Technical English, the aerospace standard for maintenance manuals, as adapted by danyuchn/asd-ste100-skill (MIT). The goal is one reading per sentence.

This mode does not use ASD's approved 900-word dictionary, because the standard restricts redistribution. It applies the principle behind the dictionary: pick the plainest common word and use it the same way every time. Do not claim STE compliance. When exact approved wording matters, as in real aircraft documentation, the author must check against the official standard.

## Pick a level

- **Strict.** Use for tool and function descriptions, error messages, procedures, agent-to-agent instructions, and safety text, meaning anywhere a wrong reading costs something. Apply every rule below.
- **Light.** Use for READMEs, PR descriptions, changelogs, and explanatory docs. Apply the sentence rules in full. Treat the word rules (marked *strict only*) as advice, because prose needs some range.

If the user does not name a level, infer it from the text type. Keep the choice to yourself unless they ask for the rule table.

## Sentence rules

| Rule | Do | Don't |
|---|---|---|
| Active voice, named actor | "The agent deletes the file." | "The file is deleted." Passive voice is fine only when the actor is unknown or does not matter. |
| One instruction per sentence | "Open the file. Read line 3." | "Open the file and read line 3, then check it." |
| Length cap | 20 words for steps, 25 for descriptions | Long chains of clauses |
| No semicolons | Two sentences | Any semicolon |
| No soft phrasal verbs | start, contact, read, remove | spin up, reach out, dive into, take off |
| Verbs, not nominalizations | "Analyze the log." | "Perform an analysis of the log." |
| Noun clusters of 3 words or fewer | "fuel pump valve" | "high pressure fuel pump inlet valve assembly" |
| No dropped words | Keep the subject, verb, and article | "Files not backed up will be lost" (which files?) |
| Simple tenses | "We received the report." | "We have received the report." Keep the compound form when it carries current relevance ("the job has completed, output is ready") or a hedge ("may have failed"), and flag it. |
| One topic per paragraph | 6 sentences or fewer | Paragraphs that mix topics |
| Lists for sequences | Numbered list for 3 or more steps or conditions | A sequence buried in one sentence |

## Word rules (strict only)

- **One word, one meaning.** Name each thing once and keep the name: always "user", never "user", "customer", and "client" for the same person. Use one verb for one action: always "check", never a rotation of "check", "verify", and "confirm".
- **Define kept jargon once.** A necessary domain term stays, with a one-line definition the first time it appears.

## Modality is content

Humanize normally cuts hedging. In this mode, cut hedge stacks but keep a single hedge that states real uncertainty.

- "It is important to note that this may potentially help" becomes "This may help."
- "The request may have failed" stays as it is. Changing it to "The request failed" makes a different claim.
- "Could be caused by X" never becomes "X is the cause."

## What this mode turns off

- The voice section (personality, opinions, uneven rhythm). Flat and literal is the correct register here.
- The "vary sentence length" check in the final scan. The length caps replace it.
- Never run this mode on marketing, creative, or persuasive copy. Use the default humanize pass for that.

## Output

- Default: the rewritten text only, the same as embedded mode.
- When a longer phrasing is kept on purpose because a safety condition, scope qualifier, or number would be lost, add one line after the text: `Kept as-is: <phrase>, <what shortening would lose>`.
- On request ("show the diff", "which rules", "before/after"), give the rule table in place of the audit bullets:

| Rule broken | Original | Rewrite |
|---|---|---|
| Present perfect | "We have received your request." | "We received your request." |

- If the text already complies, say so and change nothing.
- This mode fixes form, not substance. A hollow paragraph stays hollow. Say so instead of polishing it.
